# Review

- [fixed] harm: by default, generic mailing addresses (mortgage escrow / tax servicers, registered agents) silently merged unrelated owners, including private homeowners, into one "landlord network". Nothing warned unless the user ran `addresses` first (src/main.rs:121, src/lib.rs:334) -> `networks`/`lookup` now print a stderr warning listing addresses shared by >25 owner names that still link parcels, plus new `suspicious_addresses()` with a unit test. README explains why.
- [fixed] harm/correctness: "SMITH JOHN TR" / "Smith John Trustee" / "Co-Trustee" and the surname "CHURCH JOHN" counted as entities, so namesake private individuals were merged on name alone under the default `--link-names entities`. This broke the README's promise (src/normalize.rs:21,296) -> bare `TR` is no longer an entity marker, `CO TR` is read as co-trustee, and a leading `CHURCH` is an entity only in "CHURCH OF ...". Tests: `individual_trustees_and_surnames_are_not_entities`, `namesake_trustees_stay_apart_by_default`.
- [fixed] harm/correctness: `--link-care-of` linked on care-of parties that are private individuals ("C/O JOHN SMITH") even in entities mode (src/lib.rs:408) -> the care-of party now follows the same entity rule. Test `care_of_namesake_individuals_respect_entities_mode`.
- [fixed] correctness: `lookup` site-address matching used raw substrings, so "12 Elm St" also matched "112 Elm St" and showed another landlord's network as the user's (src/lib.rs:584) -> addresses now match on whole tokens. Test `lookup_address_does_not_match_inside_other_numbers`.
- [fixed] correctness: invalid UTF-8 was decoded lossily, so every non-ASCII Latin-1 letter became U+FFFD. Then "MUÑOZ LLC" and "MUÁOZ LLC" got the same key and were merged (src/lib.rs:53) -> non-UTF-8 cells are decoded as Latin-1. Test `latin1_letters_are_not_collapsed`.
- [fixed] correctness: in single-column addresses, the state code "FL" was read as "floor" and became `#`. With `--drop-unit` this dropped the ZIP ("MIAMI FL 33101" -> "MIAMI"), which over-merged addresses across ZIPs (src/normalize.rs:350) -> before a ZIP or at the end, `FL` is kept as Florida. Test `florida_is_not_a_floor`.
- [fixed] correctness: a "C/O ..." line in its own owner column (a common OWNER2 layout) normalized to an empty key and was thrown away, so `--link-care-of` did nothing for those files (src/lib.rs:152) -> it is now attached to the previous owner. Test `care_of_in_its_own_column_is_kept`.
- [fixed] correctness: when rows with a duplicate parcel ID were merged, raw and normalized owner lists were zipped after empty names had been filtered out, so they no longer lined up. Raw names were lost or mislabelled ("ET AL" was kept and "Beta LLC" dropped) (src/lib.rs:152) -> raw and normalized lists are now merged independently. Test `duplicate_rows_keep_raw_owner_names`.
- [fixed] correctness: `lookup` of a parcel removed by `--skip-owner-occupied` printed nothing and exited 0 (src/main.rs:256) -> it now returns a clear error. CLI test `lookup_of_skipped_parcel_is_reported`.
- [fixed] honesty/usability: an ignore-file line that matched no normalized address (for example one pasted with city/state) was silently ineffective, leaving the over-merge in place (src/main.rs:181) -> a warning is now printed. CLI test `unmatched_ignore_address_warns`.
- [fixed] honesty: the README said invalid UTF-8 was "tolerated" (it was corrupted), did not mention the trustee/care-of rules, did not warn that `--drop-unit` merges every owner in a condo building, and did not say that owner-occupied detection ignores city/ZIP -> README updated.
- [unfixed] correctness: an initials pair "L P" in an individual's name ("JONES MARY L P") becomes "LP" and so counts as an entity. Rare, and telling it apart from a spelled-out "L.P." needs heuristics beyond a minimal fix.
- [unfixed] correctness: ZIPs with a lost leading zero (New England ZIPs stored as numbers, e.g. "2134") fall back to the city. That causes missed matches, not false merges. Padding them is guesswork.
- [unfixed] honesty: the "500,000 rows in well under a minute" claim has no automated test. I checked it by hand: a synthetic 500k-row file took about 4.5 s with the release build, so the claim holds.

## Summary

The tool does what the charter allows: offline grouping of public parcel records, with sensible defaults (namesake individuals not merged on name, singletons hidden). It had several ways to misidentify people. Individual trustees, Church-surnamed people and care-of individuals were treated as entities, so namesakes were merged. Servicer addresses could silently lump homeowners together. `lookup` substring matching could point a tenant at the wrong landlord. Lossy decoding merged distinct accented names. "FL" was misread as "floor". Each correctness fix has a regression test that failed before the fix. The harm from generic addresses is reduced with a default warning, not removed, because a fixed default cap would break the largest real portfolios. `cargo fmt --check`, `clippy -D warnings`, `cargo test` (42 tests) and `cargo audit` all pass.
